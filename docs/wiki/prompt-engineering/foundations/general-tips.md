# 프롬프트 설계의 일반적인 팁

프롬프트를 설계할 때 주의할 사항들을 소개합니다:

## 단순하게 시작하기

프롬프트 설계를 시작할 때는, 최적의 결과를 얻기 위해 많은 실험이 필요한 반복적인 프로세스라는 점을 기억해야 합니다. OpenAI나 Cohere의 간단한 playground를 좋은 시작점으로 사용할 수 있습니다.

간단한 프롬프트로 시작한 후, 더 나은 결과를 얻을 때까지 점진적으로 더 많은 요소와 맥락을 추가할 수 있습니다. 이 과정에서 프롬프트를 반복적으로 개선하는 것이 중요합니다. 이 가이드를 읽으면서, 특이성(Specificity), 단순성(Simplicity), 간결성(Conciseness)이 더 나은 결과를 제공하는 경우가 많다는 것을 알게 될 것입니다.

많은 하위 작업을 포함하는 큰 작업이 있을 때는, 이를 더 간단한 하위 작업으로 분해하고 결과를 얻으면서 점진적으로 구성할 수 있습니다. 이렇게 하면 프롬프트 설계 프로세스 초기에 너무 많은 복잡성을 추가하는 것을 방지할 수 있습니다.

## 명령어(Instruction)

"Write", "Classify", "Summarize", "Translate", "Order" 등의 명령어를 사용하여 모델이 달성할 것을 지시함으로써 다양한 간단한 작업에 대한 효과적인 프롬프트를 설계할 수 있습니다.

많은 실험을 통해 무엇이 가장 잘 작동하는지 확인해야 합니다. 다양한 명령어, 키워드, 맥락, 데이터를 사용해 보고 특정 사용 사례와 작업에 대해 무엇이 가장 잘 작동하는지 확인하세요. 일반적으로, 맥락이 작업에 더 구체적이고 관련성이 높을수록 더 좋은 결과를 얻을 수 있습니다.

또한 명령어를 프롬프트의 시작에 배치하고 "###"과 같은 명확한 구분자를 사용하여 명령어와 맥락을 분리하는 것이 권장됩니다.

**예시:**
```
### 명령어 ###
Translate the text below to Spanish:

Text: "hello!"
```

**출력:**
```
¡Hola!
```

## 구체성(Specificity)

명령어와 작업에 대해 매우 구체적이어야 합니다. 프롬프트가 더 설명적이고 상세할수록 더 나은 결과를 얻을 수 있습니다. 특정 결과나 생성 스타일을 추구하는 경우 특히 중요합니다. 더 나은 결과로 이어지는 특정 토큰이나 키워드는 없습니다. 좋은 형식과 설명적인 프롬프트가 더 중요합니다. 실제로 프롬프트에 예시를 제공하는 것이 원하는 형식으로 출력을 얻는 데 매우 효과적입니다.

프롬프트를 설계할 때는 프롬프트의 길이도 고려해야 합니다. 프롬프트가 얼마나 길 수 있는지에 대한 제한이 있습니다. 얼마나 구체적이고 상세해야 하는지 생각해야 합니다. 불필요한 세부사항을 너무 많이 포함하는 것이 항상 좋은 접근 방식은 아닙니다. 세부사항은 관련성이 있어야 하고 작업에 기여해야 합니다. 이는 많은 실험과 반복을 통해 최적화해야 하는 것입니다.

## 하지 말 것보다는 할 것을 지시하기

프롬프트를 설계할 때의 또 다른 팁은 하지 말아야 할 것을 피하되, 해야 할 것을 대신 말하는 것입니다. 이는 더 많은 구체성을 권장하고 좋은 응답으로 이어지는 세부사항에 초점을 맞춥니다.

**나쁜 예시:**
```
The following is an agent that recommends movies to a customer. DO NOT ASK FOR INTERESTS. DO NOT ASK FOR PERSONAL INFORMATION.

Customer: Please recommend a movie based on my interests.
Agent:
```

**좋은 예시:**
```
The following is an agent that recommends movies to a customer. The agent is responsible for recommending a movie from the top global trending movies. It should refrain from asking users for their preferences and avoid asking for personal information.

Customer: Please recommend a movie based on my interests.
Agent:
```

## 핵심 개념

- 반복적 개선: 프롬프트를 점진적으로 개선하는 과정
- 명령어 선택: "Write", "Classify" 등 동사 사용
- 구체성의 균형: 충분한 상세함 vs 프롬프트 길이
- 명시적 지시: 부정문보다 긍정문 사용
- 구분자 활용: ### 같은 마커로 섹션 분리

## 왜 중요한가

효과적인 프롬프트 설계는 반복적 실험의 산물입니다. 이러한 팁들을 이해하면, 모든 작업에서 일관되게 더 나은 결과를 얻을 수 있습니다. 설계 원칙을 알고 있으면, 새로운 작업에 대해서도 효과적인 프롬프트를 빠르게 개발할 수 있습니다.

## 시험 포인트

- 단순함에서 복잡함으로의 반복적 접근
- 명령어의 선택과 배치
- 구체성 수준의 조정
- 프롬프트 길이와 명확성의 균형
- 구조적 마커의 활용
- 부정문 피하기
