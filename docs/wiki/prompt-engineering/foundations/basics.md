# 프롬프트 엔지니어링의 기초

## 언어 모델 프롬프팅

간단한 프롬프트로도 많은 것을 달성할 수 있지만, 결과의 품질은 모델에 제공하는 정보의 양과 프롬프트가 얼마나 잘 작성되었는지에 따라 달라집니다. 프롬프트는 모델에 전달하는 *명령어*나 *질문*과 같은 정보를 포함할 수 있으며, *맥락(Context)*, *입력값*, *예시*와 같은 추가 세부사항도 포함할 수 있습니다. 이러한 요소들을 활용하면 모델을 더 효과적으로 지시할 수 있고, 결과의 품질을 향상시킬 수 있습니다.

간단한 예시로 시작해보겠습니다.

**프롬프트:**
```
The sky is
```

**출력:**
```
blue.
```

OpenAI Playground나 다른 LLM playground를 사용하고 있다면, 위의 스크린샷처럼 모델에 프롬프트를 보낼 수 있습니다.

<!-- 이미지: OpenAI Playground 인터페이스 -->

OpenAI의 ChatGPT 모델(`gpt-3.5-turbo` 또는 `gpt-4`)을 사용할 때는 세 가지 역할(role)을 사용하여 프롬프트를 구조화할 수 있습니다: `system`, `user`, `assistant`. 시스템 메시지는 필수는 아니지만 어시스턴트의 전반적인 행동을 설정하는 데 도움이 됩니다. 위의 예시는 사용자 메시지만 포함하고 있으며, 이를 통해 `gpt-3.5-turbo` 모델에 직접 프롬프트를 보낼 수 있습니다. 예시에서 `assistant` 메시지는 모델의 응답에 해당합니다. 원하는 행동의 예시를 보여주기 위해 어시스턴트 메시지를 정의할 수도 있습니다.

위의 프롬프트 예시에서 언어 모델은 `"The sky is"` 맥락을 고려하여 의미 있는 토큰 시퀀스로 응답합니다. 하지만 출력은 예상과 달리 또는 달성하려는 작업과 거리가 있을 수 있습니다. 사실 이 기본 예시는 더 많은 맥락이나 원하는 것을 구체적으로 달성하기 위한 명시적인 지시가 필요함을 강조합니다. 이것이 바로 프롬프트 엔지니어링입니다.

이제 개선해봅시다:

**프롬프트:**
```
Complete the sentence:

The sky is
```

**출력:**
```
blue during the day and dark at night.
```

훨씬 낫지 않습니까? 위의 프롬프트에서 문장을 완성하도록 모델에 지시하고 있으므로, 결과가 훨씬 좋습니다. 이러한 방식으로 효과적인 프롬프트를 설계하여 모델에 원하는 작업을 수행하도록 지시하는 접근 방식을 이 가이드에서 **프롬프트 엔지니어링**이라고 합니다.

오늘날의 LLM은 텍스트 요약부터 수학적 추론, 코드 생성에 이르기까지 다양한 고급 작업을 수행할 수 있습니다.

## 프롬프트 포맷

위에서 매우 간단한 프롬프트를 시도했습니다. 표준 프롬프트는 다음과 같은 형식을 가집니다:

```
<Question>?
```

또는

```
<Instruction>
```

이를 많은 질의응답(QA) 데이터셋에서 표준인 질의응답 형식으로 포맷할 수 있습니다:

```
Q: <Question>?
A:
```

이러한 방식으로 프롬프트할 때를 *영샷 프롬프팅(Zero-shot prompting)*이라고도 합니다. 즉, 달성하려는 작업에 대한 예시나 시연 없이 모델에 직접 응답을 요청하는 것입니다. 일부 대형 언어 모델은 영샷 프롬프팅을 수행할 수 있지만, 작업의 복잡도와 모델이 학습한 작업에 따라 달라집니다.

구체적인 프롬프트 예시는 다음과 같습니다:

**프롬프트:**
```
Q: What is prompt engineering?
```

최근 모델들을 사용하면 "Q:" 부분을 생략할 수 있습니다. 시퀀스의 구성 방식에 따라 모델이 이를 질의응답 작업으로 이해하고 있기 때문입니다. 즉, 프롬프트를 다음과 같이 단순화할 수 있습니다:

**프롬프트:**
```
What is prompt engineering?
```

위의 표준 형식을 바탕으로, 프롬프팅의 인기 있고 효과적인 기법을 *퓨샷 프롬프팅(Few-shot prompting)*이라고 합니다. 이 기법에서는 예시(즉, 시연)를 제공합니다. 퓨샷 프롬프트는 다음과 같이 포맷할 수 있습니다:

```
<Question>?
<Answer>

<Question>?
<Answer>

<Question>?
<Answer>

<Question>?
```

QA 형식 버전은 다음과 같습니다:

```
Q: <Question>?
A: <Answer>

Q: <Question>?
A: <Answer>

Q: <Question>?
A: <Answer>

Q: <Question>?
A:
```

QA 형식을 사용할 필요가 없다는 점을 기억하세요. 프롬프트 형식은 작업에 따라 달라집니다. 예를 들어, 간단한 분류 작업을 수행할 때 작업을 시연하는 예시를 제공할 수 있습니다:

**프롬프트:**
```
This is awesome! // Positive
This is bad! // Negative
Wow that movie was rad! // Positive
What a horrible show! //
```

**출력:**
```
Negative
```

퓨샷 프롬프트는 맥락 내 학습(In-context learning)을 가능하게 합니다. 이는 언어 모델이 몇 가지 시연을 통해 작업을 학습할 수 있는 능력입니다. 우리는 영샷 프롬프팅과 퓨샷 프롬프팅에 대해 더 자세히 논의할 것입니다.

## 핵심 개념

- 프롬프트 엔지니어링: 언어 모델의 출력을 최적화하기 위해 입력을 체계적으로 설계하는 과정
- 맥락 내 학습: 예시를 제공하여 모델이 새로운 작업을 학습하는 능력
- 영샷 vs 퓨샷: 예시 없이 vs 예시를 포함하여 프롬프팅하는 방식
- 프롬프트 포맷: 명령어, 질문, 예시의 구조적 배열

## 왜 중요한가

프롬프트 엔지니어링은 LLM 시스템 설계의 핵심입니다. 동일한 모델이라도 프롬프트의 품질에 따라 결과의 정확도, 관련성, 유용성이 크게 달라집니다. 효과적인 프롬프팅은 모델의 잠재력을 최대한 활용하며, 미세 조정(Fine-tuning) 없이도 성능을 향상시킬 수 있습니다.

## 시험 포인트

- 프롬프트 설계의 기본 원리 이해
- 영샷과 퓨샷 프롬프팅의 차이점
- 맥락과 예시가 모델 출력에 미치는 영향
- 다양한 작업에 적합한 프롬프트 구조 선택 능력
- 반복적 프롬프트 개선의 중요성
