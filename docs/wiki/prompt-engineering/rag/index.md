# RAG (Retrieval Augmented Generation)

검색 증강 생성(RAG)은 LLM이 외부 지식 소스에 접근할 수 있도록 함으로써 신뢰성과 정확성을 향상시키는 현대적인 기법입니다. 이 섹션에서는 RAG의 기본 개념부터 고급 응용까지 다룹니다.

- **[LLM을 위한 RAG](rag-for-llms.md)** - RAG 파이프라인, 워크플로우, 현대 응용
- **[RAG 모델의 충실성](rag-faithfulness.md)** - 검색된 정보와 모델의 기존 지식의 상호작용
- **[RAG를 통한 환각 감소](rag-hallucinations.md)** - 구조화된 출력에서의 환각 완화 방법

## 섹션 요약

RAG는 LLM의 다음과 같은 근본적인 문제들을 해결합니다:

### 1. 지식의 고정성 (Fixed Knowledge Problem)
- **문제**: LLM의 학습 데이터는 고정되어 최신 정보를 모르는 경우가 많음
- **솔루션**: 동적으로 외부 지식 소스를 조회하여 최신 정보 활용

### 2. 환각 (Hallucination)
- **문제**: LLM이 존재하지 않는 사실을 만들어낼 수 있음
- **솔루션**: 검색된 문서를 기반으로 생성하여 검증 가능성 향상

### 3. 도메인 특화 지식 (Domain-Specific Knowledge)
- **문제**: 일반 목적 LLM이 특정 도메인의 지식 부족
- **솔루션**: 도메인 특화 문서 기반을 동적으로 활용

## RAG의 3단계 파이프라인

```
1. 인덱싱 (Indexing)
   └─ 문서 청킹 → 임베딩 생성 → 벡터 저장소 저장

2. 검색 (Retrieval)
   └─ 쿼리 임베딩 → 유사도 검색 → 관련 문서 추출

3. 생성 (Generation)
   └─ 검색 문서 + 프롬프트 → LLM → 최종 응답
```

## RAG의 핵심 개념

| 개념 | 설명 | 중요성 |
|------|------|--------|
| **임베딩** | 텍스트를 벡터로 변환 | 의미적 유사성 검색의 기초 |
| **검색** | 관련 문서 추출 | RAG 품질을 결정하는 핵심 |
| **컨텍스트** | 검색 문서를 프롬프트에 추가 | 생성 품질 및 신뢰성 향상 |
| **신뢰도** | 생성 정보의 검증 가능성 | 환각 완화 및 신뢰성 보장 |

## RAG의 장점

### 1. 신뢰성 향상
- 검색된 문서 기반으로 생성되므로 검증 가능
- 환각 현상 감소

### 2. 최신 정보 접근
- 재훈련 없이 새로운 정보 통합
- 지속적으로 변화하는 정보에 적응

### 3. 비용 효율성
- 대형 모델 재훈련 불필요
- 적절한 검색 기법으로 성능 유지

### 4. 확장성
- 다양한 지식 기반에 적용 가능
- 작은 모델로도 효과적인 시스템 구축 가능

## RAG의 과제

### 1. 검색 품질
- 관련도 높은 문서를 검색하기 어려울 수 있음
- 임베딩 모델의 성능이 전체 시스템을 좌우

### 2. 정보 충돌
- 검색된 정보가 모델의 기존 지식과 모순될 수 있음
- 모델이 어떤 정보를 신뢰할지 결정해야 함

### 3. 컨텍스트 길이
- 검색 결과로 인한 프롬프트 길이 증가
- 토큰 제한과 비용 고려

## 실제 응용 사례

### 1. 고객 지원 시스템
- 회사 정책과 FAQ 문서 기반의 자동 응답
- 실시간 업데이트된 정보 활용

### 2. 의료 시스템
- 최신 의료 문헌과 임상 가이드라인 기반의 진단 지원
- 검증된 정보만을 기반으로 생성

### 3. 법률 자문
- 법규와 판례 데이터베이스 기반의 법적 자문
- 정확한 인용과 참고 자료 제공

### 4. 기술 문서
- 소프트웨어 문서와 API 레퍼런스 기반의 개발 지원
- 최신 버전의 정보 제공

## RAG 선택 가이드

**RAG를 사용해야 할 때:**
- 정보가 자주 업데이트되는 경우
- 도메인 특화 지식이 필요한 경우
- 높은 신뢰성과 검증 가능성이 필요한 경우
- 비용 효율성이 중요한 경우

**RAG가 필요 없을 때:**
- 정적인 일반 지식만으로 충분한 경우
- 매우 빠른 응답 속도가 필수적인 경우
- 복잡한 다단계 추론이 필요한 경우
