# LLM 추론 가이드 (Reasoning LLMs Guide)

## 추론 LLM이란?

대규모 추론 모델(Large Reasoning Models, LRMs) 또는 단순히 추론 LLM은 기본적인 사고(thinking) 또는 사고의 연쇄(chain-of-thought)를 수행하도록 명시적으로 훈련된 모델입니다. 추론 모델의 인기 있는 예로는 Gemini 2.5 Pro, Claude 3.7 Sonnet, 그리고 o3이 있습니다.

**ChatGPT(o3) 및 Gemini 2.5 Pro(AI Google Studio)에서 시도해볼 프롬프트:**

```
What is the sum of the first 50 prime numbers? Generate and run Python code for the calculation, and make sure you get all 50. Provide the final sum clearly.
```

### 에이전트 RAG(Agentic RAG)

**에이전트 RAG**는 추론 모델을 활용하여 복잡한 지식 기반 또는 소스에 대한 고급 도구 사용 및 추론을 포함하는 에이전트 RAG 애플리케이션을 구축하는 시스템입니다. 복잡한 쿼리/컨텍스트를 라우팅하는 **검색 에이전트**를 추론 체인/도구(도구/함수 호출을 통해)와 함께 활용하는 것을 포함할 수 있습니다.

### LLM-as-a-Judge

자동화된 평가/검사가 필요한 애플리케이션을 구축할 때, LLM-as-a-Judge는 선택지입니다. LLM-as-a-Judge는 대량의 정보에 대한 복잡한 이해와 추론을 활용합니다. 추론 LLM은 이러한 유형의 사용 사례에 이상적입니다. 아래 예제는 LLM-as-a-Judge 에이전트(추론 모델이 지원)로 루프를 도는 평가자-최적화 에이전트 시스템을 보여줍니다. 이 에이전트는 먼저 예측을 평가하고 피드백을 생성합니다. 피드백은 현재 프롬프트, 피드백, 그리고 기본 시스템 프롬프트를 최적화하려고 하는 메타 프롬프트에 의해 사용됩니다.

### 시각적 추론(Visual Reasoning)

o3과 같은 모델은 멀티 도구 사용 기능을 활용하여 [고급 시각적 추론](https://openai.com/index/thinking-with-images/)을 수행하고 이미지에 대한 추론, 이미지 수정(확대, 자르기, 회전 등) 등의 작업을 가능한 도구로 수행할 수 있습니다. 모델은 사고의 연쇄 내에서 이미지를 사용하여 추론할 수 있습니다.

**크로스워드 퍼즐:** [https://chatgpt.com/share/681fcc32-58fc-8000-b2dc-5da7e84cf8bf](https://chatgpt.com/share/681fcc32-58fc-8000-b2dc-5da7e84cf8bf)

### 기타 사용 사례

기타 사용 사례에는 다음이 포함됩니다:

- 기술 영역의 대규모 복잡한 데이터 세트(많은 개별 문서)에서 관계 찾기 및 질문 답변
- 대규모 코드베이스 검토, 이해, 디버깅; 알고리즘 개발 및 과학 코딩에도 탁월함
- 고급 수학 문제 해결, 실험 설계, 심화된 추론이 필요한 과학 작업
- 문헌 검토 및 종합
- 지식 기반의 단계별 지침을 최적화하기 위한 루틴 생성(예: 메타 프롬팅)
- 데이터 질을 개선하기 위한 데이터 검증 및 신뢰성 향상
- 다단계 에이전트 계획(예: 심화 연구)
- QA 시스템을 위한 관련 정보 인식 및 추출
- 지식 집약적이고 모호한 작업

## 추론 LLM 사용 팁

### 일반적인 사용 패턴 및 프롬팅 팁

- **전략적 추론:** 추론 모델을 모든 부분에 사용하지 말고 LLM 기반 애플리케이션의 추론이 많은 모듈이나 구성 요소에만 사용합니다. 관심사의 분리를 적용(애플리케이션을 모듈화)하여 애플리케이션의 어느 부분에서 추론이 유용할지 쉽게 식별할 수 있도록 합니다.

- **추론 시간 스케일링(테스트 시간 계산):** 일반적으로 생각할 시간(즉, 계산)이 많을수록 대부분의 추론 모델의 성능이 더 좋습니다.

- **생각 시간:** `low`(낮은 비용 및 빠른 응답) 또는 `high`(더 많은 생각 시간과 더 많은 토큰, 느린 응답)와 같은 다양한 추론 노력 옵션을 사용할 수 있습니다. `medium`은 정확도와 속도 사이의 균형입니다.

- **명확한 지시사항:** 다른 표준 채팅 LLM과 마찬가지로 추론 모델에 달성하고자 하는 명확하고 명시적인 지시사항을 제공합니다. 단계별 세부 사항을 제공할 필요는 없습니다(아래 참조). 하지만 모델이 추측할 수 있는 가정을 제거하기 위해 필요한 고수준 지시사항, 제약 조건 및 원하는 출력을 제공하는 것이 중요합니다.

- **수동 CoT 피하기:** 지시사항에서 사고의 연쇄(단계별) 프롬팅을 피합니다. 지시사항은 단순하고 직접적이어야 합니다. 해당하는 경우 응답 제약을 지시사항에 추가합니다.

- **입력 및 출력 구조화:** 표준 LLM과 유사하게 구분자로 입력을 구조화하는 것이 좋습니다. 특히 복잡한 에이전트 애플리케이션을 구축할 때 구조화된 출력을 활용할 수도 있습니다. 대부분의 추론 모델은 JSON 또는 XML을 사용하여 출력 구조화에 대한 지시사항을 따르는 데 효과적입니다. 특별한 요구사항이 없는 한, XML을 기본 모드로 생성 콘텐츠 구조화에 사용할 것을 권장합니다. **Claude 4 같은 모델의 출력 형식은 프롬프트 구조화 방식(예: Markdown을 사용하면 Markdown 출력에 크게 기울어짐)의 영향을 받는 경향이 있습니다.**

- **퓨샷 프롬팅:** 모델이 원하는 출력을 충족하는 데 어려움을 겪는 경우, 퓨샷 시연/예제를 추가합니다. 고수준 지시사항과 이러한 것들이 일치하도록 하여 혼동을 피합니다. 퓨샷 프롬팅은 원하는 출력을 설명하기 어렵고 모델이 피하고 싶은 동작의 예를 제공할 때 특히 유용합니다.

- **지시사항에서 설명적이고 명확한 수정자 사용:** o3 및 Claude 4 같은 모델을 지시사항에서 더 명확한 수정자와 더 많은 세부사항을 사용하여 더 복잡하고 고품질의 출력(예: 코드 및 검색 결과)을 생성하도록 조종할 수 있습니다. [Claude 4 문서에서 얻음](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/claude-4-best-practices#enhance-visual-and-frontend-code-generation), 프론트엔드 코드 생성의 예로는 "마우스 오버 상태, 전환, 마이크로 인터랙션과 같은 신중한 세부 사항 추가"입니다.

### 하이브리드 추론 모델 사용

- **단순하게 시작:** 먼저 표준 모드(사고 모드 끔)를 사용하고 응답을 평가합니다. 여기서 수동 사고의 연쇄 프롬프트도 시도할 수 있습니다.

- **기본 추론 활성화:** 실수를 보고 얕은 응답을 봤지만 작업이 더 광범위한 분석/추론에서 이득을 얻을 수 있다고 믿으면 사고를 활성화합니다. 낮은 사고 노력으로 시작하고 응답의 품질을 평가합니다.

- **생각 시간 증가:** 낮은 사고가 충분하지 않으면 중간 노력으로 전환합니다.

- **더 많은 생각 시간:** 중간 노력이 충분하지 않으면 높은 노력으로 전환합니다.

- **퓨샷 프롬팅 사용:** 출력의 스타일 및 형식을 개선해야 하는 경우 시연을 사용합니다.

## 추론 모델의 제한 사항

추론 모델을 사용할 때 유의해야 할 일반적인 지속적인 문제 목록:

### 출력 품질

- 추론 모델은 때때로 혼합 언어 콘텐츠, 반복 콘텐츠, 일관성 없는 출력, 형식 문제 및 낮은 품질의 출력 스타일을 생성할 수 있습니다.
- 이러한 문제 중 일부는 모델의 프롬팅 모범 사례를 따르면 완화될 수 있습니다. 모호하고 불필요한 지시사항을 피합니다.

### 추론이 지시사항 준수에 미치는 영향

- 추론 모델과 함께 명시적 사고의 연쇄 프롬팅을 사용할 때 모델의 지시사항 준수 성능을 해칠 수 있습니다. 이는 CoT를 사용하는 방법을 더 신중하게 해야 하며, 추론 모델과 함께 전혀 사용하지 않을 수도 있음을 의미합니다.
- 다음 논문은 다음 완화 전략을 제안합니다:
  - 신중하게 선택된 예제로 퓨샷 인컨텍스트 학습
  - 자기 성찰(모델이 자신의 답변을 비판하고 수정)
  - 자기 선택적 추론(모델이 추론할 시간을 결정)
  - 분류기 선택적 추론(외부 분류기가 추론이 도움이 될지 예측)

### 과도한 사고 및 부족한 사고

- 적절하게 프롬팅되지 않으면 추론 모델은 과도하게 사고하거나 부족하게 사고하는 경향이 있습니다.
- 작업, 프로세스, 예상 출력 형식에 대해 매우 구체적으로 함으로써 이를 개선할 수 있습니다.
- 다른 개발자는 부작업을 만들고 복잡한 작업을 추론 도구(추론 모델이 지원)에 라우팅하여 이를 해결합니다.

### 비용

- 추론 모델은 표준 채팅 LLM보다 훨씬 더 비쌉니다. 따라서 디버깅 도구를 사용한 실험 및 응답 품질 평가가 항상 필요합니다.
- 불일치한 출력에서 발생하는 토큰 사용량과 비용을 추적합니다.

### 지연 시간(Latency)

- 추론 모델은 상대적으로 느리며 때때로 작업과 무관한 불필요한 콘텐츠를 출력하여 지연 시간 문제가 발생합니다.
- 이러한 지연 시간 문제는 더 간결한 프롬팅으로 피할 수 있습니다. 애플리케이션 측면에서, 스트리밍 토큰을 활용하여 인식된 지연 시간을 개선할 수도 있습니다.
- 더 작은 추론 모델 및 Claude 3.7 Sonnet과 같은 다른 모델은 더 나은 지연 시간을 생성합니다.
- **정확도를 먼저 최적화한 다음 지연 시간과 비용을 최적화하기 위해 시도하십시오.**

### 도구 호출 및 에이전트 기능 부족

- o3 같은 추론 모델이 멀티 도구 호출을 개선했지만 병렬 도구 호출이 여전히 문제가 될 수 있습니다.
- 다른 추론 모델도 명시적으로 이를 수행하도록 훈련되지 않은 경우(예: DeepSeek-R1 및 Qwen 시리즈) 도구 호출 기능이 부족합니다.
- 고급 및 더 안정적인 도구 호출을 사용하면 실제 세계에서 조치를 취할 수 있는 에이전트 시스템을 잠금 해제할 수 있습니다. 추론 LLM은 이미 매우 지식이 풍부하지만 **강력하고 동적인 도구 호출 기능** 및 물리적 세계와 디지털 세계 이해에서 더 많은 개선이 필요합니다. 멀티모달 추론은 진행 중인 연구 영역입니다.

활동적인 커뮤니티 포럼이 있습니다. 지원, 지도, 라이브 사무실 시간 참여, 전문가와의 라이브 이벤트 참여 등을 받을 수 있습니다.

## 핵심 개념

- 추론 LLM은 기본 사고와 사고의 연쇄를 수행하도록 명시적으로 훈련된 모델
- 복잡한 문제 해결, 깊은 추론, 다단계 계획이 필요한 작업에 효과적
- 에이전트 RAG, LLM-as-a-Judge, 시각적 추론 등 다양한 사용 사례 존재
- 정확도를 우선으로 최적화한 후 비용과 지연 시간을 최적화해야 함
- 전략적 추론: 모든 부분이 아닌 추론이 필요한 모듈에만 사용
- 명확한 지시사항과 구조화된 출력이 추론 모델의 성능을 크게 향상
- 하이브리드 접근: 표준 모드에서 시작 후 필요에 따라 추론 활성화

## 왜 중요한가

추론 LLM은 LLM 기반 시스템 설계에서 중요한 패러다임 변화를 대표합니다. 이들은 복잡한 추론, 멀티스텝 계획, 그리고 자율적 의사결정이 필요한 작업을 다루기 위해 기존 LLM의 한계를 극복합니다. 에이전트 시스템, 특히 심화 연구와 도구 사용이 필요한 응용 프로그램에서 전문화된 추론 능력을 활용함으로써 개발자는 더 신뢰할 수 있고 효과적인 AI 시스템을 구축할 수 있습니다. 그러나 높은 비용과 지연 시간을 고려하여 전략적으로 사용해야 합니다.

## 시험 포인트

- 추론 모델과 표준 LLM의 주요 차이점 및 각각의 적절한 사용 시나리오
- 추론 노력(낮음, 중간, 높음) 설정이 성능, 비용, 지연 시간에 미치는 영향
- 지시사항 준수 vs. 추론 능력의 트레이드오프 관리
- 에이전트 시스템에서 도구 호출 실패 및 해결 전략
- 비용 최적화와 정확도의 균형을 맞추는 실무 제약사항
