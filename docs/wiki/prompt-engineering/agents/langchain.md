# LangChain

## 개요

**LangChain**은 LLM 애플리케이션을 조립식으로 만들 수 있게 해 주는 오픈소스 프레임워크입니다. 모델 호출·프롬프트·외부 도구·메모리·[RAG](../rag/overview.md) 같은 구성 요소를 표준 인터페이스로 묶어, "LLM에 무언가를 연결하는" 반복 작업을 단순화합니다.

!!! abstract "학습 목표"
    - LangChain이 해결하는 문제(구성 요소 조립)를 설명할 수 있다
    - 체인(Chain)과 주요 구성 요소를 나열할 수 있다
    - 프레임워크 사용의 장점과 주의점을 판단할 수 있다

## 왜 프레임워크가 필요한가

LLM 앱은 보통 "프롬프트 → 모델 → 출력 파싱 → 도구 호출 → 다시 모델…"처럼 여러 단계를 잇습니다. 이걸 매번 직접 구현하면 모델·도구를 바꿀 때마다 코드를 새로 써야 합니다. LangChain은 각 단계를 **교체 가능한 부품**으로 표준화해, 모델을 바꿔도 나머지는 그대로 두게 합니다.

## 핵심 구성 요소

| 구성 요소 | 역할 |
|-----------|------|
| **모델(Model)** | 여러 LLM 제공사를 동일 인터페이스로 호출 |
| **프롬프트 템플릿** | 변수를 넣어 재사용 가능한 프롬프트 |
| **체인(Chain)** | 여러 단계를 순서대로 연결 |
| **도구(Tool)** | 검색·계산·API 등 외부 기능 연결 |
| **메모리(Memory)** | 대화·작업 맥락 유지 |
| **리트리버(Retriever)** | [RAG](../rag/overview.md)용 문서 검색 |

!!! example "체인의 개념"
    "사용자 질문 → 관련 문서 검색(Retriever) → 프롬프트에 삽입 → 모델 답변 → 형식 정리" 를 하나의 체인으로 묶으면, 이 흐름 전체를 한 번의 호출로 실행할 수 있습니다. 이것이 전형적인 RAG 체인입니다.

## 장점과 주의점

!!! success "장점"
    - 구성 요소 교체가 쉬움(모델·벡터스토어·도구)
    - 방대한 통합(수많은 LLM·DB·도구 커넥터)
    - RAG·에이전트 등 일반 패턴의 빠른 프로토타이핑

!!! warning "주의점"
    - **추상화 비용**: 내부에서 무슨 일이 일어나는지 파악이 어려워 디버깅이 힘들 수 있음
    - **빠른 변화**: API가 자주 바뀌므로 버전 고정·문서 확인 필요
    - 단순한 작업이라면 프레임워크 없이 직접 호출이 더 명료할 수 있음

복잡한 다단계·상태 관리가 필요해지면, 같은 생태계의 [LangGraph](langgraph.md)로 확장하는 것이 일반적입니다.

## 시험 대비 핵심 정리

- LangChain = LLM 앱을 **조립식 부품**으로 만드는 프레임워크
- 핵심: 모델·프롬프트·**체인**·도구·메모리·리트리버
- 대표 활용: **RAG 체인**, 에이전트
- 트레이드오프: 통합 편의 ↔ 추상화로 인한 디버깅·변화 관리 부담
