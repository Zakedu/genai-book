# LangGraph

## 개요

**LangGraph**는 [LangChain](langchain.md) 생태계에서 **상태를 가진(stateful) 다단계 에이전트 워크플로**를 만들기 위한 프레임워크입니다. 작업 흐름을 **그래프(노드와 엣지)**로 표현해, 조건 분기·반복(루프)·사람 개입 지점을 명시적으로 설계할 수 있습니다.

!!! abstract "학습 목표"
    - 체인(선형)과 그래프(분기·순환)의 차이를 설명할 수 있다
    - 노드·엣지·상태(State)의 역할을 이해한다
    - LangGraph가 에이전트에 적합한 이유를 설명할 수 있다

## 체인 vs 그래프

[LangChain](langchain.md)의 기본 체인은 **한 방향으로 흐르는** 파이프라인입니다. 그러나 에이전트는 "도구를 쓰고 → 결과를 보고 → 다시 판단하고 → 필요하면 반복"하는 **순환·분기** 구조가 필요합니다.

| 구분 | 체인(Chain) | 그래프(Graph) |
|------|------------|--------------|
| 흐름 | 선형(한 방향) | 분기·순환 가능 |
| 반복 | 어려움 | 자연스러움(루프) |
| 적합 | 정해진 순서의 파이프라인 | **자율 에이전트** |

## 핵심 개념

- **노드(Node)**: 하나의 작업 단위(모델 호출, 도구 실행, 판단 등)
- **엣지(Edge)**: 노드 간 이동 경로. **조건부 엣지**로 "결과에 따라 다른 노드로" 분기
- **상태(State)**: 그래프 전체가 공유하는 데이터. 각 노드가 상태를 읽고 갱신하며 진행
- **사람 개입(Human-in-the-loop)**: 특정 노드에서 실행을 멈추고 사람 승인을 기다릴 수 있음

```
[시작] → [계획] → [도구 실행] → (결과 충분?) ─아니오→ [도구 실행] (루프)
                                     │
                                    예
                                     ↓
                              [사람 승인] → [최종 답변]
```

!!! example "에이전트에 왜 맞는가"
    에이전트가 "검색 결과가 부족하면 다시 검색"하는 판단을 하려면 같은 노드로 되돌아가는 **루프**가 필요합니다. 선형 체인으로는 표현하기 어렵지만, 그래프에서는 조건부 엣지로 자연스럽게 만듭니다.

## 실무에서

LangGraph는 지식 그래프를 도구로 쓰는 [GraphRAG](../rag/graphrag.md) 에이전트, 다단계 리서치 에이전트, 사람 승인이 필요한 업무 자동화 등에 쓰입니다. 단, 그래프 설계 자체가 복잡도를 더하므로 **단순 파이프라인에는 과합니다** — 순환·분기·상태 관리가 실제로 필요할 때 선택하는 것이 좋습니다.

## 시험 대비 핵심 정리

- LangGraph = LangChain 생태계의 **상태 기반 에이전트 그래프** 프레임워크
- **체인=선형, 그래프=분기·순환** → 에이전트의 반복 판단에 적합
- 핵심: **노드·엣지(조건부)·상태·사람 개입**
- 복잡도 비용 존재 → 순환·분기가 필요할 때 선택
