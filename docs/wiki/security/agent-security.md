# AI 에이전트 보안 (Agent Security)

## 개요

에이전트는 단순히 답을 생성하는 것을 넘어 **실제 도구를 실행**합니다. 메일을 보내고, 코드를 실행하고, 데이터베이스를 조회하죠. 이 실행 권한 때문에, 에이전트의 보안 사고는 "잘못된 답변"이 아니라 **"잘못된 행동"**으로 나타납니다. 이 문서는 에이전트 고유의 위협 범주와 방어 원칙을 정리합니다.

!!! abstract "학습 목표"
    - 에이전트의 '과잉 권한'이 왜 핵심 위험인지 설명할 수 있다
    - 툴 포이즈닝·메모리 포이즈닝의 원리를 구분할 수 있다
    - 섀도우 AI와 에이전트 거버넌스의 필요성을 이해한다

## 위협 1 — 과잉 권한 (Excessive Agency)

OWASP는 에이전트에게 필요 이상의 권한·자율성·기능이 주어진 상태를 **과잉 권한(Excessive Agency, LLM06)**으로 규정합니다. [프롬프트 인젝션](prompt-injection.md)이 성공했을 때 실제 피해 규모를 결정하는 것이 바로 이 권한 범위입니다.

- **기능 과잉**: 쓰지도 않는 도구까지 연결해 둠
- **권한 과잉**: 읽기만 필요한데 쓰기·삭제 권한까지 부여
- **자율성 과잉**: 되돌릴 수 없는 작업을 사람 확인 없이 실행

→ 방어의 출발점은 언제나 **최소 권한 원칙**입니다.

## 위협 2 — 툴 포이즈닝 (Tool Poisoning)

에이전트가 연결한 도구([MCP](../prompt-engineering/agents/mcp.md) 서버 등)의 **설명(메타데이터)에 악성 지시를 숨기는** 공격입니다. 모델은 도구 설명을 신뢰해 읽으므로, 오염된 설명이 그대로 주입 명령처럼 작동합니다. 2026년에는 MCP SDK의 전송 방식 자체를 겨냥한 공급망 취약점이 공개되며 이 위협이 실제 사건으로 확인됐습니다.

## 위협 3 — 메모리 포이즈닝 (Memory Poisoning)

에이전트의 **장기 메모리·RAG 인덱스·벡터스토어에 악성 데이터를 미리 심어두는** 공격입니다. 한 번 오염되면 이후의 모든 작업이 그 심어진 의도를 이어받기 때문에, 일회성 인젝션보다 지속적이고 탐지가 어렵습니다.

!!! warning "왜 특히 위험한가"
    연구·보안 벤치마크들은 메모리·데이터 주입 계열 공격의 성공률이 상당히 높게 보고된다고 지적합니다(구체 수치는 실험 설정에 따라 편차가 크므로, 특정 숫자보다 "성공률이 높은 편"이라는 경향으로 이해하는 것이 안전합니다). 신뢰할 수 없는 데이터를 메모리에 넣기 전 검증하는 단계가 필수입니다.

## 위협 4 — 섀도우 AI와 거버넌스 공백

**섀도우 AI**는 보안팀이 인지하지 못한 채 조직 내부에서 운영되는 AI 도구·에이전트를 말합니다. 여러 기업 조사에서 상당수 조직이 "파악되지 않은 AI 워크플로가 이미 돌아가고 있다"고 응답하며, 이는 거버넌스의 사각지대를 만듭니다. 표준화 측면에서는 NIST 등이 에이전트 보안 표준화 논의를 진행 중입니다.

!!! note "검증 상태"
    이 문서의 섀도우 AI 도입률·공격 성공률 등 정량 통계는 조사 주체·시점·모집단에 따라 값이 크게 다릅니다. 교재 편집 시에는 라운드테이블 교차검증을 거쳐 확정 수치·출처를 각주로 고정할 예정입니다. 현재는 방향성 있는 경향으로만 서술했습니다.

## 방어 체크리스트

- [ ] **최소 권한** — 도구·스코프를 필요한 만큼만, 읽기 우선
- [ ] **인간 승인 게이트** — 결제·삭제·외부 전송은 사람 확인
- [ ] **입력 신뢰 경계** — 외부 데이터/메모리는 검증 후 사용
- [ ] **도구 출처 검증** — 공식·서명된 도구만, 설명 메타데이터 감사
- [ ] **행동 로깅·감사** — 에이전트의 모든 도구 호출 기록·추적
- [ ] **자산 목록화** — 조직 내 에이전트를 파악해 섀도우 AI 방지

## 시험 대비 핵심 정리

- 에이전트 보안의 핵심은 **과잉 권한(LLM06)** — 인젝션의 피해 규모를 결정
- 고유 위협: **툴 포이즈닝**(도구 설명 오염), **메모리 포이즈닝**(장기기억 오염)
- **섀도우 AI** = 파악되지 않은 사내 에이전트 → 거버넌스 공백
- 방어 원칙: 최소 권한 + 인간 승인 + 신뢰 경계 + 로깅
