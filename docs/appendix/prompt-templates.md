# A. 프롬프트 템플릿 모음

분야별, 목적별로 즉시 사용 가능한 프롬프트 템플릿입니다. **{중괄호} 부분을 실제 내용으로 바꾸어 사용**하세요. 구체적일수록 더 좋은 결과를 얻을 수 있습니다.

---

## 학습/연구용 (Learning & Research)

학생, 연구자, 자기개발자를 위한 템플릿입니다. 개념 학습, 시험 준비, 논문 작성을 효과적으로 지원합니다.

### 1. 논문/자료 빠른 요약

**언제 사용:**
- 긴 논문이나 자료를 빠르게 이해해야 할 때
- 핵심을 정확히 파악하고 싶을 때

```markdown
[역할]
당신은 학술 논문 분석 전문가입니다.

[작업]
다음 논문/자료에 대해 분석해주세요:

{논문 본문 또는 링크}

[분석 항목]
1. 연구 질문/목적
2. 주요 연구 방법론
3. 가장 중요한 발견 3가지
4. 이 연구의 한계점
5. 실무/후속 연구에 대한 시사점

[형식]
- 각 항목별로 3-5문장 정도로 간결하게
- 전공자가 아니어도 이해할 수 있는 쉬운 언어 사용
- 핵심 수치/통계가 있으면 반드시 포함
- 마지막에 한 문장으로 "이 연구의 가치" 요약
```

### 2. 어려운 개념 쉽게 설명받기

**언제 사용:**
- 학습 중 이해가 안 되는 개념이 있을 때
- 여러 관점에서 이해하고 싶을 때

```markdown
[주제]
{개념명}에 대해 설명해주세요.

[요구사항]
1. 한 줄 정의 (초등학생도 이해할 수 있는 수준)
2. 핵심 특징 3가지
3. 일상생활에서의 비유 (구체적인 예시)
4. 실제 활용 사례 2-3개
5. 자주 혼동되는 비슷한 개념과의 차이점

[대상 수준]
{수준: 예) 고등학생 / 대학 신입생 / 해당 분야 미경험자}

[추가]
시각 자료나 표로 정리해도 좋습니다.
```

### 3. 시험 대비 문제 자동 생성

**언제 사용:**
- 시험을 앞두고 자가 점검할 때
- 학습한 내용을 체계적으로 복습하고 싶을 때

```markdown
[자료]
다음 학습 내용을 바탕으로 시험 문제를 만들어주세요:

{학습 내용/교과서 내용 붙여넣기}

[문제 구성]
- 객관식 {개수}문항 (각 4지선다)
- 단답형 {개수}문항 (1-2줄 답변)
- 서술형 {개수}문항 (3-5줄 답변)

[조건]
- 난이도: {하/중/상}
- 각 문제별 정답과 해설 제시
- 각 문제가 어느 부분에서 출제되었는지 명시
- 함정 선택지도 포함
- 학생들이 많이 틀리는 부분 중심으로 출제

[추가]
정답지와 채점 기준도 함께 만들어주세요.
```

### 4. 토론/발표 대비 준비

**언제 사용:**
- 수업 토론이나 PT 발표를 앞두고 있을 때
- 상대 주장에 대한 반박 준비가 필요할 때

```markdown
[주제]
"{토론 주제}"에 대한 토론/발표를 준비하고 있습니다.

[나의 입장]
{내가 주장할 입장: 찬성 또는 반대}

[요청]
다음을 준비해주세요:

1. 내 입장의 핵심 논거 3-4개 (각각 근거 포함)
2. 상대방이 제시할 가능성이 높은 반론 3-4개
3. 각 반론에 대한 효과적인 대응 방안
4. 뒷받침할 수 있는 통계/사례/뉘앙스
5. 토론 중 사용할 수 있는 표현/은유
6. 예상 질문 TOP 3과 답변 예시

[추가]
토론을 할 때 피해야 할 함정도 알려주세요.
```

### 5. 연구논문을 위한 문헌 검토 구조화

**언제 사용:**
- 학위논문이나 학술 글쓰기를 시작할 때
- 연구 주제와 관련된 기존 연구를 정리해야 할 때

```markdown
[연구 주제]
{연구 주제 또는 연구 질문}

[연구 분야]
{분야: 예) 심리학, 마케팅, 환경공학}

[요청]
이 주제에 대한 문헌 검토 구조를 다음과 같이 제시해주세요:

1. 이 분야의 연구 흐름 (시간순서대로 3-4개 단계)
2. 핵심 이론/프레임워크 소개 (각 이론별 개요)
3. 주요 연구자/기관들
4. 연구 방법론 분류 (정량적/정성적/혼합 등)
5. 기존 연구의 공통 발견점
6. 연구 간극(research gap) - 아직 답하지 못한 질문
7. 학술 데이터베이스 검색용 추천 키워드 (한글/영문)

[주의]
구체적인 논문명은 제시하지 말고, 연구의 큰 흐름과 방향을 중심으로.
```

### 6. 강의/책 내용 완벽 정리

**언제 사용:**
- 강의를 들은 후 내용을 체계적으로 정리할 때
- 읽은 책/자료의 핵심을 한 장으로 요약하고 싶을 때

```markdown
[학습 자료]
다음 강의 내용/책 내용을 정리해주세요:

{강의 필기 또는 책 내용}

[정리 형식]
1. 전체 주제 한 줄 요약
2. 목차 구조 (대주제 → 소주제)
3. 각 섹션별 핵심 포인트 (불릿 형식)
4. 중요 용어/개념 정의
5. 현실에 적용할 수 있는 팁 3가지
6. 다음에 공부할 관련 주제 제안

[길이]
A4 1-2페이지 분량

[추가]
마인드맵이나 플로우차트 형식도 좋습니다.
```

## 업무/비즈니스 (Business & Professional)

직장인, 기업가, 프리랜서를 위한 템플릿입니다. 효율적인 소통, 보고, 기획을 지원합니다.

### 7. 상황별 이메일 작성

**언제 사용:**
- 중요한 업무 이메일을 보내기 전에
- 어떤 톤으로 작성할지 고민될 때

```markdown
[상황]
{상황 설명: 예) 거래처에 납기 지연을 사과하고 재계약 조건 제시}

[수신자 정보]
- 역할: {역할: 예) 거래처 구매팀장}
- 관계: {관계: 예) 10년 거래 관계, 우호적}
- 직급/성향: {성향: 예) 보수적, 수치를 중요시 함}

[포함해야 할 내용]
1. {내용 1: 예) 지연 이유 간단히}
2. {내용 2: 예) 솔직한 사과}
3. {내용 3: 예) 해결 방안/보상안}

[톤]
{톤: 예) 정중하고 진심 어린, 하지만 전문적으로}

[길이]
{길이: 예) 200-300자}

[첨부]
{첨부물: 있으면 명시}

[추가 요청]
- 자신감 있게 들리되 겸손하게
- 핵심을 먼저 제시하고 설명은 뒤에
```

### 8. 회의록 정리 및 액션 아이템 추출

**언제 사용:**
- 회의가 끝난 후 빠르게 회의록을 정리할 때
- 결정사항과 할 일을 명확히 하고 싶을 때

```markdown
[회의 정보]
- 회의명: {회의명}
- 일시: {년월일 시간}
- 참석자: {참석자 이름 (역할)}
- 회의 목적: {목적: 예) Q1 사업 전략 수립}
- 진행자: {진행자명}

[회의 내용]
{회의 메모, 녹취록, 또는 주요 발언 붙여넣기}

[정리 형식]
1. 회의 핵심 의제 {개수}개 요약
2. 주요 논의 사항별 의견 대립점
3. 최종 결정 사항 (명확한 YES/NO)
4. 액션 아이템:
   - 항목 | 담당자 | 기한 | 우선순위
5. 다음 회의 예정 및 검토 항목
6. 추가 논의가 필요한 이슈

[추가]
각 액션 아이템별로 배경(WHY)도 간단히 포함.
```

### 9. 보고서 초안 작성

**언제 사용:**
- 팀장이나 임원진에게 진행 상황을 보고해야 할 때
- 주간/월간/분기 보고서를 작성할 때

```markdown
[보고서 유형]
{유형: 예) 주간 업무 보고 / 프로젝트 현황 보고 / 판매 실적 보고}

[보고 기간]
{기간: 예) 2024년 1월 1주차}

[보고 대상]
{대상: 예) 팀장, 임원진}

[포함할 내용]
1. 핵심 성과/진행 상황
   - {성과 1: 수치 포함}
   - {성과 2}
   - {성과 3}

2. 주요 이슈/리스크
   - {이슈 1 및 대응 방안}
   - {이슈 2}

3. 예산 현황 (해당하면)
   - 집행률: {수치}%

4. 다음 주/월 계획
   - {계획 1}
   - {계획 2}

[형식 요청]
- 분량: A4 1-2페이지
- 스타일: 불릿 포인트 중심, 간결하게
- 핵심 수치는 굵은 글씨 또는 강조
- 시각적 표현 (그래프/표) 권장
- 어조: 객관적이고 실행 지향적
```

### 10. 신규 프로젝트/제품 기획서 구조 잡기

**언제 사용:**
- 새로운 프로젝트나 제품을 기획하기 시작할 때
- 기획안의 전체 틀을 잡고 싶을 때

```markdown
[기획 주제]
{기획 주제: 예) 신규 모바일 앱 런칭}

[배경/현황]
{현황 설명: 예) 고객들로부터 OO 기능 요청이 증가. 경쟁사도 출시 중.}

[프로젝트 규모]
- 예산: {예산 범위}
- 기간: {진행 기간}
- 담당팀: {팀 구성}

[요청]
다음과 같은 기획서 구조를 만들어주세요:

1. 목차 제안 (전체 섹션 구성)
2. 각 섹션별 들어갈 핵심 내용 (주요 포인트 3-5개)
3. 설득력을 높이기 위해 꼭 포함해야 할 데이터/근거
4. 경영진이 할 만한 주요 질문 3-5개와 답변 전략
5. 자주 하는 실수 및 피해야 할 함정
6. 필요한 첨부 자료 체크리스트

[청중]
{청중: 예) CEO, 이사회, 외부 투자자}

[발표 시간]
{시간: 예) 20분}
```

### 11. 피드백 요청 - 전문가 수준의 검토

**언제 사용:**
- 완성한 기획안, 제안서, 보고서를 발표 전에 검토받고 싶을 때
- 약점을 찾아 개선하고 싶을 때

```markdown
[검토 대상]
다음 문서를 검토해주세요:

{기획안/제안서/보고서 전문 붙여넣기 또는 요약}

[검토 관점]
1. 논리적 흐름
   - 주장이 일관성 있게 전개되는가?
   - 각 섹션이 자연스럽게 연결되는가?

2. 설득력 분석
   - 가장 설득력 있는 부분
   - 보강이 필요한 부분 (근거 부족 등)

3. 완성도 체크
   - 누락된 중요한 요소가 있는가?
   - 불필요한 부분은?

4. 표현/글쓰기 개선점
   - 문체의 일관성
   - 어려운 표현이나 오류
   - 가독성 개선 제안

5. 첫 인상 평가
   - 전체 완성도 (10점 만점): ?
   - 한 문장 종합 평가

[우선순위]
가장 중요한 개선점 TOP 3을 먼저 알려주세요.

[추가]
전문가 관점에서 솔직한 피드백 부탁드립니다.
```

### 12. 데이터/자료 기반 의사결정 보고서

**언제 사용:**

```markdown
[의사결정 상황]

[선택지]
1. {옵션 A: 세부 설명}
2. {옵션 B: 세부 설명}
3. {옵션 C: 세부 설명}

[평가 기준 및 가중치]
- {기준 1 (가중치: %%)}
- {기준 2 (가중치: %%)}
- {기준 3 (가중치: %%)}
- {기준 4 (가중치: %%)}

[요청]
1. 각 선택지의 장단점 정리 (표 형식)
2. 평가 기준별로 각 옵션 점수 산정
3. 종합 평가 및 추천 옵션 명시
4. 추천 이유 (근거 제시)
5. 이 결정의 리스크 및 대응 방안
6. 최종 선택지 실행 시 주의사항

[추가]
```

## 코딩/기술 (Technical & Development)

개발자, 프로그래머를 위한 템플릿입니다. 코드 작성부터 배포까지 전 과정을 지원합니다.

### 13. 새로운 기능 코드 작성

**언제 사용:**
- 구현해야 할 기능이 있을 때
- 코드 작성보다 로직 설계가 우선일 때

```markdown
[프로그래밍 언어]
{언어: 예) Python 3.11 / JavaScript (Node.js 18) / Java 17}

[프레임워크/라이브러리]
{프레임워크: 예) Django, React, Spring Boot}

[기능 요구사항]
{구현할 기능 상세 설명:
- 무엇을 하는가?
- 어떤 상황에서 필요한가?}

[입출력 명세]
- 입력: {입력 형식 및 예시}
- 출력: {출력 형식 및 예시}
- 제약 조건: {성능, 용량 등}

[필수 사항]
1. 에러 처리 포함 (예상 가능한 에러 케이스)
2. 주석으로 핵심 로직 설명
3. 사용 예시 코드 포함
```

## 프롬프트 작성 팁

### 효과적인 프롬프트 작성 5가지 원칙

!!! info "프롬프트 작성 팁"

    1. **구체성 (Specificity)**
        - 모호한 표현 피하기: "좋은 글" → "1500자, 블로그용, 친근한 톤"
        - {중괄호}에 구체적인 내용 입력

    2. **맥락 제공 (Context)**
        - 배경 정보 충분히 제시
        - 예: "누구에게 왜 설득해야 하는가?"

    3. **형식 지정 (Format)**
        - 원하는 출력 형식 명시
        - 예: "표 형식", "불릿 포인트", "단계별"

    4. **제약 조건 명시 (Constraints)**
        - 길이, 톤, 대상 등 제약 사항 명확히
        - 예: "200자 이내", "전문가용", "상/중/하 난이도"

    5. **반복 개선 (Iteration)**
        - 첫 결과에 만족하지 않으면 수정 프롬프트
        - 예: "더 간결하게", "더 구체적인 사례 추가"

### 템플릿 커스터마이징 방법

| 단계 | 방법 | 예시 |
|------|------|------|
| 1단계 | {중괄호} 부분을 실제 내용으로 대체 | {논문명} → "How LLMs Learn Concepts" |
| 2단계 | 불필요한 항목 삭제 | 해당 없으면 그 섹션 지우기 |
| 3단계 | 필요한 항목 추가 | 나만의 요구사항 추가 |
| 4단계 | 우선순위 조정 | 중요한 것부터 배치 |
| 5단계 | 예시 데이터 붙여넣기 | 실제 데이터/자료 포함 |

### AI 도구와의 상호작용 팁

```markdown
첫 번째 프롬프트: 전체 기본 틀을 요청
    ↓
결과 검토: 어느 부분을 수정할지 파악
    ↓
수정 프롬프트: "더 간결하게", "사례 추가", "톤 변경" 등
    ↓
완성본 도출: 최종 검토 및 정리
```

### 자주 하는 실수와 개선법

| 실수 | 원인 | 개선 방법 |
|------|------|----------|
| 너무 일반적인 결과 | 구체성 부족 | 더 자세한 배경정보 제공 |
| 예상과 다른 톤 | 톤 명시 부족 | "전문적이면서 친근하게" 명시 |
| 길이가 안 맞음 | 길이 지정 안 함 | 구체적인 글자수/페이지 명시 |
| 너무 복잡함 | 단순화 요청 안 함 | "초보자 수준으로" 명시 |
| 누락된 부분 있음 | 요구사항 불충분 | 체크리스트 작성 후 검증 |
